## 1. 背景

HGhub 现有 Tauri 2 + React 19 四端客户端（Windows / macOS / Android / iOS-WebView），iOS 端已能编译、能播 HLS，但本质是 WKWebView 承载的 Web UI：竖滑列表的跟手性、原生手势、PiP/AirPlay/锁屏、启动与内存都不如原生。详见根目录 [AIRead.md](../AIRead.md)。

本项目新增一个**独立的纯原生 iOS 工程**，用 SwiftUI + AVPlayer 重写 iOS 端，作为 iOS 交付物；其余三端继续用 Tauri，不动。

## 2. 目标与非目标

### 2.1 目标

| ID | 目标 | 判定 |
|---|---|---|
| G-01 | 纯原生 UI | 无 WKWebView 承载主界面；仅系统分享/外链等系统弹层 |
| G-02 | 播放体验对齐或优于 WebView | AVPlayer 直连 HLS，支持系统全屏/PiP/AirPlay/锁屏控制 |
| G-03 | 与上游协议一致 | 复用现有边缘信封、播放接口、封面解密、线路规则 |
| G-04 | 可维护 | 文档先行；分层 MVVM + Repository；契约 fixtures |
| G-05 | 可学习 | 代码结构清晰，关键决策有 ADR，不堆砌框架 |

### 2.2 非目标

- 不替换 Tauri 的 Windows / macOS / Android 端。
- 不做 iPad 专属布局、横屏、分屏（v1 仅 iPhone 竖屏；后续可评估）。
- 不做离线下载 / 缓存整剧 / 后台批量下载（与项目“不给上游加压”的约束冲突）。
- 不做多账号、家长控制、推送、小组件、Watch App、国际化。
- 不做 App Store 上架、内购、广告、卡密、VIP。
- 不改上游接口、不逆向签名、不引入服务端。
- 不搬运 Rust/React 代码；协议照抄，实现重写。

## 3. 用户与场景

**用户**：项目作者本人（单用户、自用学习）。无账号体系运营需求。

**核心场景**：

1. 打开 App → 首页竖滑刷短剧 → 点暂停 / 双击点赞 / 选集 / 看评论。
2. 看到一半退出 → 下次从“观看历史”按集数与秒数续播。
3. 搜索剧名 / 按分类浏览 / 看榜单 → 进入播放。
4. 登录后点赞、收藏、关注、评论；未登录可浏览、可看本地历史。
5. 上游域名失效 → 设置里切换固定线路或镜像线路 → 重试。
6. 看“吃瓜”图文 → 正文图片正常显示 → 点赞/收藏/评论。
7. 换主题、清缓存、检查更新、看网络诊断。

## 5. 功能需求

> 优先级：P0 = MVP 必须；P1 = 对齐现有 App；P2 = 可选。
> 每条需求都要有可验收的行为，不以“页面画出来”为完成。

### 5.1 账号（FR-AUTH）

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-AUTH-01 | 用户名 + 密码登录 | P0 | 成功后 token 存 Keychain，`AppState.session` 更新，重启仍登录 |
| FR-AUTH-02 | 注册（用户名/密码/可选邮箱） | P1 | 成功后同登录态 |
| FR-AUTH-03 | 退出登录 | P0 | 清 Keychain 与服务端会话，回到未登录态 |
| FR-AUTH-04 | 启动恢复会话 | P0 | 冷启动读 Keychain + 本地用户资料，不阻塞首页 |
| FR-AUTH-05 | 401 统一处理 | P0 | 任意请求 401 → 清会话 → 弹登录，不重复弹 |
| FR-AUTH-06 | 未登录拦截 | P0 | 点赞/收藏/关注/评论前检查登录，未登录弹登录 |

## 6. 非功能需求

| ID | 类别 | 要求 | 验证 |
|---|---|---|---|
| NFR-01 | 性能 | 冷启动 ≤2s 到可交互；Feed 滚动 60fps；切条 ≤500ms 出画面 | 真机/模拟器手动 + Instruments |
| NFR-02 | 内存 | 常规使用 <300MB；只保留 1 个 AVPlayer + 1 条预加载 | Instruments Allocations |
| NFR-03 | 网络 | 失败重试 3 次（350ms 递增）；超时 20s / 连接 10s；走系统代理 | 断网/弱网手动 |
| NFR-04 | 健壮性 | 上游字段缺失/类型漂移不崩溃；解码失败显示错误态 | fixtures + 手动 |
| NFR-05 | 安全 | token 只在 Keychain；日志不打印 token；只允许 HTTPS | 代码审查 |
| NFR-06 | 兼容 | iOS 17.0+；iPhone 竖屏；安全区/灵动岛适配 | 多设备模拟器 |
| NFR-07 | 无障碍 | 主要按钮有 accessibilityLabel；支持动态字体 | VoiceOver 抽查 |
| NFR-08 | 可维护 | 文档与代码同步；关键路径有单元测试；SwiftFormat/SwiftLint 通过 | CI/本地 |
| NFR-09 | 合规 | 保留免责声明与非商用许可；不提供下载；不高频轮询 | 代码审查 |
| NFR-10 | 可观测 | Debug 下 Pulse 可看 API 请求；播放错误写 `errorLog` | Debug 构建 |

## 7. 约束与假设

| ID | 约束/假设 | 影响 |
|---|---|---|
| C-01 | 上游把 `/api/**` 收敛为 `POST /api/edge/request` 信封 | 所有业务请求走统一信封；播放接口例外 |
| C-02 | 播放接口必须直连，body 为 `{}` | 不能走信封，否则 `请求无法处理` |
| C-03 | 封面是 AES-128-CBC 密文 | 需要本地解密后再解码 |
| C-04 | 域名会漂移 | 线路切换是第一优先级能力 |
| C-05 | 不搬 Rust 内核 | 网络/解密/线路用 Swift 重写，按契约对齐 |
| C-06 | 自用签名 | 免费账号 7 天 provisioning；不追 App Store |
| C-07 | 上游可能限流/封禁 | 不做下载、不高频轮询、缓存不关小 |
| C-08 | 单用户 | 不做多账号切换、权限体系 |
| C-09 | 网络依赖系统代理 | 模拟器复用 macOS 代理；真机需 Wi-Fi 代理；不在 App 内做代理配置（v1） |

## 8. 验收与完成定义

一个里程碑算完成，必须同时满足：

1. 文档中的任务全部完成，状态回写到 [开发计划](development-plan.md)。
2. `xcodebuild build` 通过（Debug，模拟器）。
3. 新增逻辑有对应单元测试或手动验收记录。
4. 没有新增 `TODO` 未登记到计划；没有“先这样”的临时代码。
5. 关键决策变更已写入 [ADR](decisions.md)。

## 9. 术语

| 术语 | 含义 |
|---|---|
| 边缘信封 | `POST /api/edge/request`，body 内再描述真实 method/path/body |

| 线路 | 上游 base URL；固定 2 条 + 发布页镜像 |
| 封面 | 列表/详情图，AES-128-CBC 密文 |

| 本地库 | 收藏、喜欢、关注、观看历史、搜索历史（本地存储） |
